# Приватность и ограничения

## Локальность — инвариант

Файл `result.json` читается через `FileReader` в память вкладки
и обрабатывается в Web Worker на той же машине.
Сетевых запросов с содержимым чата нет: в коде отсутствуют
`fetch` и `XMLHttpRequest`, страница работает офлайн и в режиме полёта.

Следствие: реальный экспорт нельзя коммитить, прикладывать к задачам
и отправлять по сети — только синтетическая фикстура в тестах.

## Валидация на границе

Вся ненадёжная строка файла валидируется один раз в `parse`:

- не-JSON и чужая структура — внятная ошибка формата;
- HTML-экспорт отклоняется с подсказкой включить
  «Машиночитаемый экспорт (JSON)» в настройках Telegram;
- даты нормализуются через `date_unixtime`, авторы извлекаются
  из `from` / `actor` / `name`;
- DOM-оверрайды `localStorage` чистятся молча, без падения карты.

## Лимиты и деградация

- Файл больше 200 МБ: обработка продолжается, UI показывает
  предупреждение о возможном замедлении.
- Участников больше двух: режим «пересечения» скрывается,
  остаются «вместе» и голоса отдельных участников.
- Пустые авторы и сервисные сообщения не ломают подсчёт:
  они проходят через общий конвейер как сообщения без слов.

## Что это значит для пользователя

Если карта не построилась —checklist: это JSON-экспорт из Telegram Desktop
или AyuGram, а не HTML; файл не обрезан; в чате есть текстовые сообщения.
Ничего никуда не загружается, можно безопасно пробовать снова локально.
