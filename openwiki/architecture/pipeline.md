# Конвейер обработки текста

Поток идёт строго по стадиям: `parse → tokenize → canon/intern → filters → tally`.
Всё выполняется в воркере с прогрессом по числу сообщений.

## Parse: граница доверия

`parse.ts` — единственная точка входа ненадёжных данных.
Принимает строку JSON, возвращает `ChatExport`:

- извлекает `from` / `actor` / `name` как авторов, нормализует даты через `date_unixtime`;
- сплющивает Telegram-сущности (`flatten`): строки и объекты с `type`/`text`;
- чистит DOM-оверрайды `localStorage` молча;
- чужой формат (например HTML-экспорт) отклоняет внятной ошибкой
  с подсказкой включить машиночитаемый JSON;
- файл больше 200 МБ пропускает дальше, но поднимает предупреждение в UI.

## Tokenize: единицы и классы

`tokenize.ts` режет части текста на токены с классом `plain | tech | digits`:

- обычный текст — по буквам и цифрам, нижний регистр, `ё → е`;
- сущности `code` и `link` идут отдельным классом `tech`;
- единица — предложение внутри одного сообщения;
  соседние единицы одного сообщения связываются слабее.

## Canon и Intern: нормализация без словарей

Лемматизаторов со словарями нет по решению проекта.
`canon.ts` — лёгкий стеммер по окончаниям:
русские окончания списком по последней букве, латинские `ing/ed/es/s`,
с guard-условиями на минимальную длину остатка.
Защита от ложных склеек (`STEM_DOMINANCE = 25`): если остаток — самостоятельное
частотное слово корпуса, стемминг не выполняется.

`Intern` присваивает каждой канонической форме числовой id
и копит карту поверхностных форм `forms` с частотами.
Повторная встреча той же поверхности — это hit без пересчёта canon.
Диапазон id ограничен (`MAX_TOKEN_ID`), переполнение — явная ошибка.
Числовые ключи пар (`edgeKey`) экономят строковые аллокации в tally.

## Filters: что попадает на карту

`filters.ts` хранит стоп-слова RU/EN, корни мата, маркеры смеха,
технические и числовые классы. `FilterCfg` — это show-flags:
`true` оставляет категорию на карте, `false` роняет её до tally.
Кастомные списки мата и смеха добавляются поверх встроенных.

## Tally: частоты и веса связей

`tally.ts` строит две структуры:

- `counts`: частота токена по каждому автору;
- `pairs`: статистика пар — внутриединичные встречи `nX`
  с затуханием `1/d` в окне 4 и межъединичные с весом `0.3`.

Три уровня связей сообщений:

1. явный reply — вес `1.0`, разрыв во времени игнорируется;
2. соседние сообщения с разрывом до 10 минут — вес `0.7`;
3. большой разрыв — связи нет.

`smartMerge` опционально склеивает опечатки и варианты по триграммам
(Жаккар ≥ 0.5, только слова от 6 символов), чтобы варианты не плодили узлы-двойники.

## Кэш конвейера

`PipelineCache.resolve` переиспользует стадии между пересборками:
токенизация одна на чат, tally/merge — по два слота на фильтры,
так что переключение туда-обратно бесплатно.
Смена фильтров не повторяет токенизацию без нужды.
Прогресс отдаётся стадиями: токенизация, подсчёт, склейки, выборка, раскладка.
