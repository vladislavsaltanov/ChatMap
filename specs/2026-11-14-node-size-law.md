# План: градация размеров нод

Дата: 2026-11-14. Запрос: «градацию размера нод ещё сильнее; поменьше разбивать,
побольше — объединять в больший тир».

## 1. Что было

`nodeFitSize` (`src/core/geometry.ts`): `2.8 + 73.2·(count/max)^0.85`. Линейная
нормировка давила хвост в пыль: при `max = 3000` слово с count 1/10/100 получало
2.9/3.4/6.9 px (неразличимо), а хаб — 76 px (одно слово towered над картой).

## 2. Правка

| Что | Как |
| --- | --- |
| `SIZE_GAMMA` 0.85 → 0.62 | низ 1–100 расходится на ~3.3–10.7 px вместо ~2.9–6.9 (полоса шире на ~85%) |
| `SIZE_MAX` 76 → 68 | верх 500–max сжимается 24–68 вместо 19–76; топ сливается в тир |
| `SIZE_MIN` | не тронут (2.8) — пыль остаётся пылью |

0.62 лежит внутри старого 0.42–0.7 диапазона, который когда-то давал решётку;
разница — бюджет площади `footprintScale`, которого тогда не было: он гасит
лишний метраж равномерным скейлом, а не уплотнением соседей.

## 3. Проверка

- `npm run typecheck` — 0; `npm run test` — 260 passed (пин `hub ≈ 76` → `68`,
  остальные ассёрты живы без правок: rare < 8, hub/rare ≥ 10, mid > rare·2).
- A/B `node tools/shot-shape.mjs` (seed фиксирован, 400/2000/271, order 250):

| | overlap at1 / at06 / at15 | minGap at1 | gap p90 at1 |
| --- | --- | --- | --- |
| было | 0.12 / 0.04 / 0.20 | −10.4 | 12.4 |
| стало | 0.14 / 0.08 / 0.28 | −16.1 | 18.8 |

Отрицательный minGap был уже в базе — схлопывания не привнесены, прирост
умеренный, решётки нет (p90 зазоров вырос). Census меток из соседнего спека
на новом коде: 27 → 83 → 126 → 79 → 44 подписей по ratio 1 → 0.25,
flicker ≤ 3, plateMismatch 0.

## 4. Рычаг отката

Если overlap поползёт на реальных экспортах — первой откатывать гамму
(→ 0.7), а не крышку: крышка держит тир хабов, гамма — цену площади.
