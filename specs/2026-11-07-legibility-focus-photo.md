# План 2026-11-07 (5) — читаемость, эго-подписи, снимок узла, тихие рёбра

Статус: **РЕАЛИЗОВАНО** (вердикт:
`specs/verifications/2026-11-07-legibility-focus-photo.md`).
Предыдущее: `specs/2026-11-07-overview-spine.md` (РЕАЛИЗОВАНО,
вердикт `specs/verifications/2026-11-07-overview-spine.md`).

## 0. Отзыв пользователя
1. При наведении **или** выборе ноды связанные ноды должны иметь включённые
   текста — видно слово каждой связанной ноды.
2. Нужна возможность сделать фото просто выделенной ноды. Сейчас невозможно.
3. Читаемость упала: ноды близко друг к другу, текст не виден издалека.
   Текст должен появляться **гораздо раньше**.
4. При приближении всё ещё визуальный шум: рядом идущие линии надо
   «склеить» **в любом случае, при любом LOD**.
5. Линии намного прозрачнее: проявляются только при наведении **или** при
   сильном приближении. И тоньше (с учётом п.4).

## 1. Диагноз по коду

| Пункт | Причина в текущем коде |
|---|---|
| 1 | `mapStyles.ts`: `whenState:'isActive'` форсирует подпись только при `g.pinActive`; `isHighlighted` форсирует только центральную ноду и только при `lodScale >= 6`. При ховере соседи (`isActive: true, isHighlighted: false`) остаются на `baseLabelVisibility` → `'auto'`/`'hidden'`, а правило `when: !isActive` при `hasActiveSubgraph` вообще прячет подписи остальных. Пин уже форсирует, ховер — нет. |
| 2 | Единственная кнопка `PNG` вызывает `downloadAsPNG` всей карты. Обзорного API «снимок узла» нет; `@sigma/export-image` умеет `cameraState`, `withTempRenderer`, `width/height` — но не используется. |
| 3 | `zoomToLabelSizeRatioFunction = zoomSizeRatio` → на ratio 2 шрифт делится на 2 (6.7 px), на 3.4 — на 3.4 (4 px). `labelAlphaFor` обнуляет малые ноды уже при `lodRatio >= 1`, средние при `> 1.2`; `labelRenderedSizeThreshold: 1` дополнительно отсекает подписи пыли; `labelDensity: 2` даёт `ceil(2/r²)` подписей на ячейку. Итог: с расстояния слов не видно. |
| 4 | `bundleEdges()` склеивает только внутри `hub:сектор` и ячеек `c<dir>:<mx>:<my>`, но `pull` < 1 и `lane = ±cell*0.05` оставляют зазор между прядями; на зуме-ин этот зазор виден как пучок отдельных линий. Подавление `rank`/`skeleton` работает только на `fadePhase` (обзор), т.е. на детали шум возвращается. |
| 5 | `edgeOpacity()` на обзоре даёт p50 0.004, но на зуме-ин `fade → 0` возвращает 0.19…1.0 у сотен рёбер; `layerAxon` рисует `fil` до 1.5 px и белый `mix(..., 0.75*s)`. |

Ключевое различие с прошлым раундом: обзор уже «хребет», но **деталь** по-прежнему
шумная. П.4 и п.5 лечатся geometriей + абсолютным (не LOD-зависимым) порогом
проявления, а не очередным `fadePhase`.

## 2. Дизайн

### 2.1 П.1 — подписи всей эго-сети на ховере и пине
`egoActive(g) = hasActiveSubgraph || pinActive || photoMode`.
Для `isActive` и `isHighlighted`:
- `labelVisibility: 'visible'` (минует `LabelGrid`, `labelBlocked`, LOD-альфу);
- `visibility: 'visible'` и полный `size` (иначе узел-пыль не рендерится и текст не появится);
- `labelSize` скомпенсирован по зуму (см. 2.3), `labelColor` в полную альфу.
Неактивные ноды при активном подграфе остаются без подписей — фокус сохраняется.

### 2.2 П.2 — снимок выделенной ноды
Кнопка `Фото` в шапке `.nodepanel` (видна только при пине) → `NodePanel.onPhoto`
→ `MapView.nodePhotoDataUrl()`.
Механизм: `drawOnCanvas(mainRenderer, { width:1200, height:900, cameraState,
withTempRenderer })`. Временный рендерер получает `photoMode: true`:
последнее правило стилей прячет все узлы без `state.isActive` и гасит все рёбра
без `state.isActive`. На снимке остаётся **выделенная нода + её соединённые
соседи с подписями** (ровно то, что требует п.1) на фоне `--paper`.
Камера сама кадрирует bbox активных узлов: `ratio = max(bw·scale/(W−2·pad),
bh·scale/(H−2·pad))`, где `scale` измерен через `graphToViewport` временного
рендерера; `x/y` = центр bbox. Скачивание — локальный `<a download>` с
`canvas.toDataURL('image/png')`, имя `chatmap-<слово>.png`. Сеть не используется.

### 2.3 П.3 — текст виден гораздо раньше
- Новый `labelZoomRatio(r)` в `geometry.ts`: `r<1 → sqrt(r)` (как сейчас),
  `r>=1 → min(1.7, r^0.45)` вместо `r`. Шейдер делит кегель на эту функцию,
  а стиль `labelSize` умножает на неё → **постоянный экранный кегель** на всех
  зумах (на r=3.4 было 4 px, станет 14.5 px).
- `labelInside(attrs, g)`: центрированная подпись только если `fitKegel` по
  **отрендеренному** радиусу проходит; иначе `labelPosition:'right'` и светлый
  текст. Иначе постоянный кегель вылезет за сжавшийся пузырь.
- Рампы `labelAlphaFor`: средние ноды до `2.2` (было `1.2`), малые до `1.8`
  (было `1.0`); хабы не гаснут; ослаблен затухающий хаб-фэйд на зуме-ин.
- `labelRenderedSizeThreshold: 0`, `labelDensity: 2 → 6`,
  `labelGridCellSize: 160 → 120` → `ceil(6/r²)` подписей на ячейку.
  `resolveLabelBoxes` по-прежнему убирает пересечения (зазор 4 px).
- Базовый кегель внешних подписей 13.5 → 14.5, минимум `fitKegel` 11 → 12.

### 2.4 П.4 — склейка при любом LOD
Геометрия считается один раз в воркере и **не зависит от камеры** — значит
склейка должна быть в `bundleEdges()`, а не в style/LOD. Добавить финальный
проход «snap» в нормализованном базисе каждого ребра:
- контрольные точки P1/P2 переводятся в `(u,v)` собственного chord
  (безразмерно, поэтому рёбра разной длины сравнимы);
- группы по `(направление mod π, ячейка mid-point ×2)`;
- для групп `n>=2` — взвешенное среднее `(a1,b1,a2,b2)` и подтяжка каждой
  пряди к нему на `0.88`, затем обратно в мировые координаты.
Плюс `lane` `cell*0.05 → cell*0.012` и усиление `pull` проходов 1–2.
Ограничение `|C − C_straight| ≤ 0.26·len` сохранено (не даёт изломов).
`r>=0.88` делает пряди одного коридора визуально одной линией на любом зуме,
веер остаётся только у концов, у своих нод.

### 2.5 П.5 — тихие тонкие линии
```
edgeReveal(r) = 1 − smoothstep(0.42, 0.85, r)        // 1 на сильном зуме-ин, 0 на обзоре
edgeOpacity  = freq·ends·spine·skeleton·isolated · (0.015 + 0.62·edgeReveal(r))
```
Итого: на обзоре p50 ≈ 0.0001, на r=0.32 максимум ≈ 0.63 (а не 1.0).
Активные рёбра (`whenState:'isActive'`) остаются яркими — это и есть «при
наведении». Тоньше: `fil` 0.18+1.15·s → 0.10+0.55·s, glow ×0.4,
белый примес 0.75·s → 0.45·s (активным возвращается 0.75 через `pulse`),
квад `1.4+3w+1.4b → 1.6+2w+0.6b`, активный `+0.8 → +0.35`,
`minEdgeThickness 1 → 0.6`.

## 4. Критерии приёмки
- Preflight зелёный: typecheck 0 ошибок, все тесты (≥ 156), build 0 ошибок.
- Ховер **и** пин форсируют подписи у центра и всех активных соседей;
  `Escape` сбрасывает; неактивные ноды подписей не имеют.
- На ratio 2 и 3.4 подписи читаемы (экранный кегель ≈ 14.5 px), число
  видимых подписей кратно выше, чем было; пересечений 0.
- Рёбра: opacity p50 на r=1 ≈ 0, на r=0.32 ≤ 0.63; активные при ховере > 0.85;
  толщина нити ≤ 0.75 px; пряди коридора совпадают в средней трети.
- Кнопка `Фото` отдаёт PNG 1200×900 только с выделенной нодой и её соседями,
  0 исключений, данных в сеть нет.
- Скриншоты и замеры CDP на фикстуре, плотной синтетике и реальном экспорте;

## 5. Риски
| Риск | Мера |
|---|---|
| Форсированные подписи соседей перекроются | `resolveLabelBoxes` прячет неактивных; активных <= 12; при нужде увеличить зазор |
| Постоянный кегель вылезет за пузырь | `labelInside` по отрендеренному радиусу, `right` для сжатых хабов |
| Слишком много подписей на обзоре | density/grid калибруются CDP-замерами, `labelBlocked` сохраняется |
| Склейка создаст изломы/петли | нормализованный базис + существующий clamp 0.26·len |
| `drawOnCanvas` не увидит обновлённый graphState | явный `refresh()` + два rAF в `withTempRenderer` |
| Снимок пустой из-за autoRescale | камера считается по `graphToViewport` временного рендерера, ratio clamp 0.08…4 |

## 6. Уточнения, найденные при реализации
- **Camera Sigma v4**: `cameraState.x/y` — нормализованные координаты `[0,1]`, а не
  мировые. Первый снимок получился пустым, пока центр не стал считаться через
  `graphToFramedGraph({x,y})` внутри `withTempRenderer`. `ratio` считается из
  `px/world`, измеренного `graphToViewport` того же временного рендерера.
- **Подписи и `lodBoost`**: density-биас (для 600 нод ×1.74) душил слова уже на
  2× отдалении. Решения по тексту переведены на РЕАЛЬНЫЙ `cameraRatio`;
  `lodRatio` остался только за телами нод. Рампы продлены: средние до 3.4,
  малые до 2.6, хабы не гаснут. Замеры: 600/1212 → 140 подписей на r=1,
  50 на r=2, 3 крупных хаба на r=3.4 (было ~0 / 0 / 0).
- **Шум на зуме-ин**: одной геометрической склейки мало — 819 рёбер с альфой
  0.12 всё равно читались как сетка. Добавлено подавление «лишних прядей» на
  ВСЕХ LOD: `spine = 1/(1 + rank·(1.1·dense + 0.6·fade))`,
  `skeleton = 1 − (0.85·dense + 0.15·fade)·smoothstep(6,22,tractRank)`,
  `dense = min(1, 1.6·mapDensity)`. Малые карты (`mapDensity=0`) сохраняют все
  пряди, плотные — только хребты. Видимых рёбер на зуме-ин: 819 → 71 (реальная
  карта), 447 → 164 (синтетика 271/535), 28 → 28 (фикстура).
- **Баланс подписей**: зазор `resolveLabelBoxes` 4 → 8 px; активные ноды эго-сети
  получили приоритет 500/1000 в расчёте коллизий.
- **Тоньше**: `fil` 0.18+1.15·s → 0.10+0.55·s, glow ×0.4, квад 1.6+2w+0.6b,
  `minEdgeThickness 0.6`; активные рёбра сохраняют белый примес через `pulse`.
- Кнопка `Фото` в `.nodepanel` (рядом с «Авто» и «✕») видна только при пине.
  Снимок содержит выделенное слово **и его соединённых соседей с подписями** —
  ровно тот фокус, который требует п.1; остальной граф скрыт `photoMode`.
