# Дизайн: fBm-клякса (силуэт фигуры)

Дата: 2026-11-15. Статус: `[STATUS: DRAFT — ждёт аппрува]`. Подход A утверждён пользователем.

## 1. Намерение и зачем

Фигура расселения нод должна читаться как горизонтальное «чернильное пятно» —
fBm-деформированный эллипс с рваным краем (6 референсов пользователя:
X/Y ≈ 260/90, амплитуда ≈ 0.47R, частота 2–3 по окружности, 3–5 октав,
лакунарность ≈ 2, gain 0.45, режимы radial + 2D-vector domain warp).
Зачем: текущая фигура читается как «круг/диск с антеннами»; нужна органическая
клякса, уникальная для каждой генерации.

## 2. Цели / не-цели / анти-цели

- Цели: рваный fBm-силуэт; процедурная уникальность на каждый open (новый сид —
  новая клякса); стабильность при переключателях фильтров; внутренняя
  неоднородность сохраняется (доли, пыль, каньоны).
- Не-цели: равномерная заливка (явно запрещено пользователем); привязка выступов
  к размеру нод (в выступе может быть что угодно); смена топологии связей.
- Анти-цели: решётка/кольцо/шар; гомогенизация плотности варпом; дрейф силуэта
  при фильтрах; сломанные S1/S4/S5.

## 3. Ограничения

- Чистая логика в `src/core/` (тестируема, vitest); детерминизм: тот же сид —
  побайтово та же фигура (S7 живёт); `Math.random` запрещён, только
  целочисленный хеш-решётчатый noise + `hashAt`-стиль сидирования.
- `holdAspect(2.0)` остаётся последним (S1-гейт не трогаем); инвариант 4
  (переиспользование кадра при фильтре) не ломается.
- Тяжёлое — в воркере; main не трогаем.

## 4. Подходы

- **A. Пост-варп готовой раскладки (выбрано).** После `resolveCollisions` +
  `containTail`, до `holdAspect`: радиальная fBm-модуляция края
  (вес = нормированный радиус: центр untouched, край full) + слабый
  2D-vector domain warp всей плоскости. Бесшовность — выборкой шума по
  окружности `(cos θ, sin θ)·freq`, как в референсах. Порты рёбер едут
  тем же полем (они в мировых единицах к этому моменту). Почему он:
  топология и каньоны нетронуты (варп гладкий и мелкий против длин рёбер),
  S4/S5/зазоры живы; цена — один проход O(N).
- **B. Ре-грамматика размещения (отвергнут).** Сажать ноды сразу внутрь
  деформированного эллипса (пуассоновский диск + отсев по полю). Цена:
  хоронит доли/канвас-механику и половину гейтов; связи — длинные хорды.
  Не выбран: противоречит требованию неоднородности внутри.

## 5. Решение (что именно строим)

- Новый `src/core/blob.ts`: `valueNoise2(x, y, seed)` (решётка + smoothstep),
  `fbm(x, y, seed, octaves=4, lacunarity=2.0, gain=0.45)`,
  `blobWarp(p, centroid, span, seed)` → смещение:
  `edge = smoothstep(0.35, 1.0, r/R)` (r — радиус от центроида),
  `radial = edge * (fbmCircle(θ) - 0.5) * 2 * EDGE_AMP`,
  `domain = DOMAIN_AMP * (fbm(vec) - 0.5)`,
  итог clamp по `MAX_WARP`. Центроид пинится (вычитаем поле в центроиде).
- `graph.ts layout()`: warp точек И портов (мировые единицы) после
  `containTail`, до `holdAspect`. На reuse-пути варп не пересчитывается
  (позиции уже варпнуты, поле — функция координат → стабильно при фильтрах).
- Параметры стартовые: `EDGE_AMP = 0.22 * span/2`, `DOMAIN_AMP = 0.05 * span/2`,
  `FREQ = 2.5`, октавы 4. Точная калибровка — стендом (`shot-shape`),
  числа в спек.
- Гейты (новое в `tests/blob.test.ts` + S-зонд): детерминизм побайтово;
  смена сида меняет силуэт (дисперсия радиуса края отличается);
  `|d| ≤ MAX_WARP` для всех нод; рваность края (стд. радиуса vs угол)
  в вилке [ragged_min, ragged_max]; неоднородность: CV плотности
  до/после варпа в пределах ±10% (варп не гомогенизирует); S1/S4/S5 зелёные.
