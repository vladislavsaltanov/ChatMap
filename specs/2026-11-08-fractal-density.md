# План 2026-11-08 (13) — сильный фрактальный шум, зазоры, рыбий глаз

Статус: **РЕАЛИЗОВАНО** (вердикт:
`specs/verifications/2026-11-08-fractal-density.md`).

Отзыв заказчика: «ноды сейчас как-то равномерно разбросаны по плоскости. нет
такого, что где-то ноды плотнее, где-то совсем мало. добавь больше сильного
фрактального шума в генерацию, но контролируй, что ноды не генерируются слишком
близко друг к другу. при приближении можешь даже слегка отдалять ноды друг от
друга (как рыбий глаз)».

## 0. Диагноз
`before13-ratio1.png` (плотная карта, 271 узел) — ровная эллиптическая
решётка. Причины:
1. ForceAtlas2 (`scalingRatio: 16000`) сам по себе расталкивает все пары и
   даёт почти равномерный диск.
2. `warpPlane()` — преобразование, зависящее только от `(угол, радиус)`: оно
   мнёт **контур**, но не создаёт локальных сгустков и пустот внутри.
3. `fractalNoise()` тоже угловое (fBm по `angle + radius`), т.е. это шум
   силуэта, а не плотности плоскости.

Итог: нужен **двумерный** fBm по `(x, y)`, применённый после укладки, и
релаксация, которая не размазывает получившиеся сгустки обратно в решётку.

## 1. Что делаем

### 1.1. Ядро: поле плотности (`src/core/graph.ts`)
- `valueNoise(x, y, seed)` — гладкий value-noise на целочисленной решётке,
  детерминированный целочисленный хеш (никакого `Math.random`).
- `fractalDensity(x, y, phases, seed)` — fBm на 5–6 октавах с **domain warp**:
  координаты выборки сдвинуты другим шумом. Возвращает `[-1, 1]`.
  Экспортируется для тестов.
- `fractalClusterPlane(points, phases, seed, strength)` — новая стадия после
  `warpPlane()`: для каждого узла считается градиент `fractalDensity` на трёх
  масштабах (крупный → средний → мелкий) и узел сдвигается по градиенту с
  затухающим шагом. Шаг тем больше, чем ниже локальная плотность: узлы из
  «пустых» зон уходят в бассейны, узлы в сгустках почти не двигаются.
  Так получаются плотные фрактальные гроздья и почти пустые карманы.
- Константы: 48 проходов, три масштаба `freq = 1.75 / 4.10 / 9.30` с шагами
  `0.050 / 0.028 / 0.014` от `maxR`; `urgency = clamp01(0.58 − 1.35 · D)` —
  в пустой зоне узел идёт полным шагом, у пика плотности останавливается.
- Сила `strength` растёт с размером графа (`clamp01((N - 12) / 80)`):
  маленькие фикстуры и инвариант «сильно связанные узлы ближе» не ломаются.
  Стадия включается только при `fullRun` и `N >= 12` (кешированные позиции
  при фильтрации не перекашиваются повторно).

### 1.2. Ядро: гарантированный зазор
- Сгустки создают новые пересечения. Поэтому сразу после кластеризации идёт
  **совместная релаксация**: `K` проходов «притяжение по градиенту плотности →
  один проход `resolveCollisions`», затем финальный проход `resolveCollisions`
  до сходимости. Отталкивание на каждом шаге не даёт кластеру «взорваться» и
  расползтись по всей плоскости, а финальный проход гарантирует минимум
  `r1 + r2 + padding` для каждой пары.
- `resolveCollisions` не меняется (его контракт и тесты сохраняются); меняется
  только то, как часто его вызывает `layout()`.
- `padScale` даже **увеличен** (`64 → 84` минимум): зазор стал больше, чем был,
  а контраст плотности даёт не «упаковка вплотную», а опустевшие зоны между
  бассейнами. Замер: `minPair` 164 → 184 мировых единиц, пересечений 0;
  на экране твёрдые тела маркеров не касаются ни на одном зуме
  (мин. зазор ≥ 4 px на r1 и ≥ 4.9 px на r0.4). В плотных гроздьях мягкие
  ореолы квадов перекрываются (до ~9 px) — это и даёт вид слитного скопления.

### 1.3. UI: рыбий глаз при зуме
- `fisheyePoint(x, y, cfg)` в `src/core/geometry.ts` — чистая функция:
  радиальное увеличение вокруг центра камеры
  `d → d · (1 + 0.22 · strength · exp(-2.4 (d/R)²))`.
  Вблизи фокуса локальные расстояния растут ~на 22 %, к краю (~1.5R) эффект
  сходит на нет. Максимальный сдвиг ≈ 0.06R, т.е. «слегка».
- `CustomGraphState` получает `fisheyeX/Y/Radius/Strength`. `MapView.applyView()`
  считает центр камеры в мировых координатах и `R` (~360 экранных px) через
  `viewportToGraph`, силу — по `ratio` (0 при `ratio >= 1`, 1 при `ratio <= 0.4`).
- `MAP_SIGMA_STYLES.nodes[0]` получает `x`/`y` как функции от `graphState`:
  Sigma v4 поддерживает позиции в стилях, поэтому смещение подхватывают узлы,
  рёбра, подписи, picking и photo-export (стили копируются `getStyles()`).
  `autoRescale: 'once'` замораживает кадрирование, поэтому эффект не дёргает
  камеру.
- `computeLabelBlocked()` считает блокирующие боксы по тем же смещённым
  координатам, иначе подписи «отстанут» от маркеров.

## 3. Критерии приёмки
- На обзоре видны **сгустки** и **почти пустые зоны**. Замер на 271 узле
  (до → после): пустые ячейки сетки `0.25 → 0.43`, CV локальной плотности
  `1.09 → 1.57`, пик/медиана `3 → 6.5`, nn p90/p10 `3.06 → 3.36`.
  На 600 узлах: `0.19 → 0.37`, `1.28 → 1.57`, `4.5 → 8.3`.
- Ни одна пара узлов не ближе `r1 + r2 + padding` в мировых координатах;
  на экране тела маркеров не слипаются.
- При `ratio 0.55 / 0.32` узлы у центра камеры расходятся, при `ratio >= 1`
  карта идентична базовой.
- Hover / pin / Escape / PNG / фото узла работают; подписи не отстают от
  маркеров; 0 ошибок консоли и GLSL.
- Preflight зелёный: typecheck, все тесты, build.

## 4. Риски
| Риск | Мера |
|---|---|
| Кластеризация разорвёт смысловые связи | поле гладкое, соседние узлы сдвигаются одинаково; сила растёт с N |
| Отталкивание снова выровняет плотность | притяжение повторяется каждый проход, а не один раз до релаксации |
| Финальная релаксация «взорвёт» сгусток | шаг притяжения затухает, зазор задан один раз и не ослабляется |
| `x`/`y` в стилях конфликтуют с Sigma | v4 явно поддерживает позиции в стилях; `enableNodeDrag` по умолчанию `false` |
| Рыбий глаз вызывает петлю камеры | конфигурация пишется в graph state, сравнение в `applyView` не даёт лишних `setGraphState` |
| Рост времени укладки на 600 узлах | фиксированное число проходов, замер в вердикте |
