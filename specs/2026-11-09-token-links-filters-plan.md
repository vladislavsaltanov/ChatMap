## 6. Фикс мат-фильтра (09.11, поверх шагов 1-5)

Жалоба: не ловит «похуй», «долбаеб», «заебись» и прочие. Причины: правило
требовало совпадения с начала слова (префиксы не снимались), не хватало
корней, суффикс ≤4 резал длинные формы, дефисные компаунды не разбирались.

- Префиксы: снимается один глагольный префикс (длиннейший первым),
  ъ/ь после него отбрасывается (подъебнуть, съебать). Незнакомая дата
  не наказывается — по аналогии с adjacent-правилом.
- Новые корни: долбоеб/долбаеб, еблан, ебло, ебищ, ебок, пидор/пидар/
  пидорас/пидрил, гандон, залуп.
- Суффикс ≤8 (охуительный, ебанувшийся, ебальник). Корни достаточно
  специфичны, невинные слова покрыты allowlist + тестами.
- Дефисы: каждая часть проверяется теми же правилами независимо
  (ебать-копать ловится, бляха-муха чистая).
- Allowlist сохранён и проверяется для целой и stripped-формы.

Проверка: filters + tally 41/41, весь сьют 186/186, tsc чист.

## 7. Плотность карты на зуме (09.11)

Жалоба: карта плотная, особенно при приближении. Замер на синтетике 6000 сообщ:
слабые рёбра в ~6 раз длиннее сильных (медианы 10742 vs 1803).

- `lengthFade(reach, strength)` в `geometry.ts`: растворение длинных рёбер
  по геометрическому reach (длина/медиана), сила только смягчает, вето нет.
  Покрыт тестами в `geometry.test.ts`.
- Транзитный каллинг в `mapview.applyView`: sigma рисует ВСЕ рёбра всегда
  (frustum-culling нет), поэтому на зуме вьюпорт пересекали десятки линий.
  Скрываются рёбра, не лежащие целиком во вьюпорте (+12% поля); рёбра
  сфокусированного эго-соседства освобождены. Diff через setEdgeState,
  O(edges) на апдейт камеры.
- Найдено по пути: кастомные стили рёбер вытеснили дефолтный маппинг
  `isHidden -> visibility`, поэтому скрытие не работало — добавлено явное
  правило `visibility` в `mapStyles.ts`.

Проверка: скриншоты до/после через playwright-core + системный Chrome
(браузерный тул требует BetterChromium): глубокий зум — 500/500 транзитных
скрыто, средний зум — 77 локальных видно, овервью без изменений.
Сьют 189/189, tsc чист, build ок.

## 2. Подходы (brainstorm)

- **A. «Только соседи» (выбран).** Связи: внутри сообщения как сейчас
  (`1/d`, меж-юнит `0.3`) + reply `1.0` + соседние сообщения в порядке
  экспорта: gap ≤ `ADJACENT_CLOSE_MS` → `0.7`, gap больше → `0`.
  Старая same-author серия (120с/30 токенов) удаляется как частный случай.
  Плюсы: прямо реализует требуемые 3 уровня, O(n), детерминировано.
- **B. Скользящее окно.** Каждое сообщение связано со всеми в окне с затуханием.
  Отклонён: размывает 3 чётких уровня, O(n·w), сложнее тестировать.
- **C. Гибрид A + сохранить burst-серии.** Отклонён: две перекрывающиеся
  механики — та же путаница, что сейчас.

Решения (мои, по поручению «приступай»; порог — константа, легко крутить):
- `REPLY_WEIGHT = 1.0` (явный ответ важнее времени, gap игнорируется).
- `ADJACENT_CLOSE_WEIGHT = 0.7`, `ADJACENT_CLOSE_MS = 10 мин`
  (120с слишком жёстко для живого диалога).
- Большой разрыв → `0` связей, не «минимальная» (минимальные веса — шум,
  который потом всё равно режется `minWeight`).
- `dateMs = 0` (дата неизвестна) → считать CLOSE (не наказывать за отсутствие
  данных; у Telegram-экспорта даты всегда есть).
- Cross-author adjacent → `nCross` (как reply чужому; режим «Пересечения»
  покажет и их — это и есть пересечение голосов). Same-author → `nX`.
  Reply себе → `nX` (как сейчас).
- Max-не-сумма сохраняется: пара внутри сообщения (`1.0`) + adjacent (`0.7`)
  → `1.0` (существующий `relax`/`seriesMax` переиспользуется).
- Соседство — по **сообщениям** (все юниты A × все юниты B), не по юнитам.
  Юниты без id (только в тестах) считаются отдельными сообщениями.
  Service/пустые сообщения пропускаются, соседство через них сохраняется.

## 3. Фильтры (пересборка)

1. Семантика `false = скрыто` сохраняется (дефолты и поведение не меняются),
   чинятся лейблы: «Показать: мат / смех / код и ссылки / числа» + тултипы.
2. Новый флаг `stopwords: false` (дефолт скрыты = текущее поведение) — пятая
   равноправная категория вместо вечного скрытого правила.
3. Кастомные списки применяются **всегда** как доп-правила своей категории.
4. Разделение типов: `FilterCfg` теряет `topN/minWeight` (остаются только
   фильтры); отбор живёт в `ViewCfg` (уже есть в `select.ts`).
   Провод `controls.getCfg() → main.ts → worker {type:'update'}` не меняется
   по форме (`FilterCfg & ViewCfg`), правится только разбор в `worker.ts`.
5. `filterCacheKey` += `stopwords`. UI: группа «Слайдеры» → «Отбор» с подписями.
6. Счётчик отсеянного — скип (YAGNI; эффект виден на карте).
