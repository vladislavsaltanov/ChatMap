# Design — ponytail-audit fix pass

Статус: дизайн зафиксирован, ревью `oracle` учтено. Код не менялся.

## Intent

Закрыть 15 находок аудита `ponytail-audit` от 10.11.2026: 3 Must fix, 7 Should fix, 5 Nice to have. Цель — убрать неправильные состояния после смены файла, укрепить границу парсинга, убрать тихие ошибки, снизить стоимость больших карт и удалить лишний код.

Причина: сейчас preflight зелёный, но ошибки проявляются на последовательностях «открыть A → неудачно открыть B», «ховер → новый файл», «кривой экспорт», «очень большой словарь» и «отказ localStorage». Обычные юнит-тесты эти последовательности не ловят.

Принятое допущение: пользователь запросил детальный план, поэтому дизайн и план сохраняются в `specs/`, без отдельного раунда согласования. Перед реализацией план всё равно требует ревью и выбора способа исполнения.

## Goals

- Устранить 3 Must fix без изменения архитектуры.
- Добавить проверки на 5 ключевых классов отказа из Review Focus.
- Сохранить зелёный Preflight и 193+ теста.
- Не добавить ни одной зависимости и ни одного сетевого вызова.
- Удалить лишние строки там, где аудит показал дублирование или одноразовую обёртку.

## Non-goals

- Не переписывать пайплайн на новую архитектуру.
- Не добавлять UI-фреймворк, линтер, CI, state.yaml или новый test harness.
- Не добавлять новые режимы в `tools/e2e-headless.mjs`; использовать только существующий `fixture` smoke и ручные DevTools-проверки.
- Не добавлять словарные лемматизаторы.
- Не трогать реальные экспорты чата.
- Не включать 3 мелкие формулировочные заметки, которые аудит явно оставил за скобками.
- Не реализовывать кандидаты B/C из `specs/2026-11-09-perf-pass-a-plan.md`.

## Anti-goals

- Один большой коммит «пофиксил аудит»: скроет отдельные дефекты и нарушит `CONVENTIONS.md`.
- Тихий `catch` без изменения UI-состояния.
- Новые generic-хелперы с одним вызывающим.
- I/O-функция в `src/core/`, которая одновременно что-то возвращает.
- Проверка только `npm run test` без ручных браузерных кейсов для worker/UI-состояний.

## Constraints

- `Preflight зелёный до следующего шага`: `npm run typecheck && npm run test && npm run build`.
- `Тесты только на src/core/ (чистая логика), vitest`; UI и sigma — ручная проверка по критериям этапов.
- `Тяжёлые вычисления — в воркере; main рисует`.
- `Никогда не отправлять данные чата по сети`.
- `Никогда не коммитить реальный экспорт чата — только синтетическая tests/fixtures/`.
- `Никаких UI-фреймворков и лишних зависимостей`.
- `Интерфейс и тексты — на русском, телеграфно`.
- Комментарии и docstrings в коде — строго на английском, короткие и технические.
- `Conventional Commits`; `main` защищена; найденный дефект — отдельным коммитом.
- File-scoped validation на каждом шаге; полный Preflight — только на completion gate.

## Approaches

### A. Один коммит на все 15 находок

Плюс: меньше коммитов. Минус: нельзя изолировать красный гейт, нарушается правило «баг по пути — отдельный коммит», ревью смешивает доверительные границы, UI-состояние и перфоманс. Отвергнут.

### B. Три независимых плана по подсистемам

Плюс: формальная декомпозиция. Минус: находки 1, 2, 5 и 11 лежат в одной последовательности «файл → worker → main → render»; планы дубировали бы одни и те же fixtures и browser checks. Отвергнут.

### C. Один план, вертикальные срезы по риску, отдельные коммиты

Выбран. Каждая задача меняет один доверительный контур, имеет свой test/verification и свой commit. Сначала Must fix, затем границы парсинга и данных, затем тесты и скорость, затем удаление лишнего кода. UI-последовательности проверяются вручную через DEV-хук `window.__mapview`, без новых CLI-режимов. Полный Preflight — в конце.

## Design decisions

1. `src/core/worker.ts`: сброс `chat`, `pipelineCache`, `positionsCache` выполняется до `parse()`. Успешный результат присваивается через локальный `nextChat`.
2. `src/ui/mapview.ts`: `render()` явно сбрасывает `pinnedId`, highlight, tween-значения и `customGraphState` до построения нового графа.
3. `src/core/parse.ts`: два boundary-хелпера — `parsePositiveInt` для целых id и `parseFinitePositiveNumber` для дат. Оба принимают только конечные числа и строки `/^\d+$/`; ISO-даты остаются на `Date.parse`.
4. `src/core/intern.ts`: экспортируется `MAX_TOKEN_ID = 2 ** 24 - 1`. `intern()` бросает `RangeError` только когда `nextId > MAX_TOKEN_ID`; id `MAX_TOKEN_ID` остаётся валидным. `src/core/tally.ts` импортирует константу вместо локального `KEY_BASE`, а `edgeKey()` отвергает id вне `[1, MAX_TOKEN_ID]`.
5. `src/core/tally.ts`: `dropFor` экспортируется; дубликат в `tests/tally.test.ts` удаляется.
6. `src/core/labelOverrides.ts`: чистый Query `applyLabelOverrides(raw, changes)` возвращает сериализованный JSON или `null`. `src/ui/nodepanel.ts`: Command `commitLabelOverrides(changes)` выполняет один `localStorage` write и бросает при ошибке; `renderForms()` ловит ошибку и оставляет старую подпись. «Авто» удаляет три ключа одним вызовом.
7. `src/core/graph.ts`: `collisionCandidatePairs()` строит сетку из текущих позиций в начале каждого pass; список кандидатов не кэшируется между pass. Сохраняются существующие quality-тесты на 600 узлов.
8. `src/core/worker.ts`: `runPipeline()` делится на `resolveData`, `buildLayoutInput`, `buildMapMessage`; сигнатуры фиксируются в плане.
9. `src/core/tally.ts`: per-pair `Set` заменяется на одну структуру отметок без аллокаций на каждую пару.
10. `src/ui/controls.ts`: таймер debounce инлайнится; `src/core/debounce.ts` и `tests/debounce.test.ts` удаляются.
11. `src/core/graph.ts`: комментарий о «test graphs under 271» обновляется под 600-узловой тест.
12. Браузерные проверки: `node tools/e2e-headless.mjs fixture` остаётся smoke-кейсом. Проверки A/B/C и storage-failure выполняются вручную в DevTools на `?fixture=1`; новые режимы CLI не добавляются.

## Success criteria

- Все 15 находок имеют задачу и либо тест, либо явную ручную проверку.
- Must fix 1 и 2 проверены ручными DevTools-кейсами A и B.
- Новые юнит-тесты: `parsePositiveInt` / `parseFinitePositiveNumber`, `MAX_TOKEN_ID`, `dropFor` из продакшена, `applyLabelOverrides`, `collisionCandidatePairs` на 1000 узлах.
- Отказ `localStorage.setItem` проверен ручным DevTools-кейсом; подпись не меняется.
- `npm run typecheck && npm run test && npm run build` зелёный; число тестов ≥ 193.
- `git status` не содержит реальных экспортов, `dist/` и временных логов.
- Итоговый отчёт сохранён в `specs/verifications/2026-11-10-ponytail-audit-fix.md`.

## What is left to the builder

Точные имена функций, сигнатуры, тестовые значения и команды проверки зафиксированы в `specs/2026-11-10-ponytail-audit-fix-plan.md`. Исполнителю не нужно выбирать модель, зависимости или структуру файлов.
