# 2026-11-12 — рост ноды при наведении/нажатии без анимации

Статус: **ИСПРАВЛЕНО**.

## Симптом

Наводишь на слово или кликаешь его — тело мгновенно становится на 12% больше, между кадрами
ничего нет. Уводишь курсор — так же резко возвращается к базовому размеру.

## Корневая причина

Размер подсвеченной ноды задан в ветке `whenState: 'isHighlighted'` (`src/ui/mapStyles.ts`):

```text
quadOf(core) * 1.12 * (1 + 0.30 * promote) * enterFactor
```

1. `1.12` — литерал, а не твин. Он срабатывает в тот же кадр, в котором `swap()` ставит
   `isHighlighted`, то есть попа нет ни на входе, ни на уходе из подсветки.
2. `promote` твинится только из `MapView.pin()` (`to('promote', 1, 220)`), поэтому на ховере
   верхние 30% вообще не существуют, а на пине анимируется лишь подъём 30% поверх мгновенных 12%.
3. Механизм затухания буста был наполовину вырезан: `SubgraphAnimator` крутит поле `release`
   (`mapview.focusSubgraph`: `jump('release', 1)` + `to('release', 0, 90)`), `SubgraphHighlight`
   помечает ушедший центр `released: true` / `releasedAt`, в `subgraphAnim` отдаётся
   `releaseAlpha` в граф-состояние — но **ни одна стиль-функция `releaseAlpha` не читает**, а
   флаг `released` объявлен в `CustomNodeState` и нигде не проверяется. Твин крутится вхолостую.

Итог: единственный источник роста — булев флаг, поэтому размер меняется ступенькой.

## Правка

1. `src/core/geometry.ts` — чистая функция `egoNodeScale(grow, promote)`:
   `(1 + 0.12·grow) · (1 + 0.30·promote)`, аргументы клампятся в 0..1. Множители остаются
   перемножением, поэтому финальные размеры не меняются (ховер ×1.12, пин ×1.456).
2. `SubgraphAnimator` — новое поле твина `grow` (шаг квантования 40, как у остальных быстрых полей).
3. `mapStyles.ts`:
   - ветка `isHighlighted` берёт `egoNodeScale(g.growAlpha, g.promote)` вместо литерала 1.12;
   - ветка «вне эго-сети» (она же ловит `released`) получает `size`, где буст гасится
     `releaseAlpha` — ушедший центр уменьшается, а не снапается.
4. `mapview.ts`:
   - `focusSubgraph`: на смену цели `jump('grow', 0)`, а сам твин роста стартует кадром позже.
     Замер зонда: первый отрисованный кадр ховера стоит ~172 мс (фан + атлас подписей на
     программном растеризаторе), твин, запущенный в нём, сгорает до первого шага —
     `pairs` показывал `[0.05 @34мс, 1 @206мс]`. Отложенный старт отдаёт анимации чистые кадры;
   - уходящему центру `release` стартует с ТЕКУЩЕГО `grow` (быстрый проход по словам не
     подбрасывает тело вверх);
   - `fadeToIdle`: `to('grow', 0, 120)` синхронно с `dim`, к моменту `clear()` буст уже нулевой;
   - `resetInteractionState` и стартовые граф-состояния получают `growAlpha: 0`, фото — `1`.
5. Повторный клик по уже подсвеченному слову не перезапускает рост (иначе тело сначала
   сжалось бы на кадр) — цель сравнивается с `SubgraphHighlight.centerKey()`.

## Проверка

Зонд `grow` в `tools/shot-shape.mjs` (400 слов / 859 связей): наведение на слово и покадровое
чтение `getNodeDisplayData(key).size`. В скобках — значение твина `grow` и время от события.

| замер | до правки | после |
| --- | --- | --- |
| кадры роста (серия) | `67.44 → 75.31` (2) | `67.24 → 67.64 → 70.87 → 75.31` (4) |
| кадры до/после, пара «твин, размер, мс» | `[0.05, 67.44, 34] → [1, 75.31, 206]` | `[0, 67.24, 34] → [0.05, 67.64, 204] → [0.45, 70.87, 261] → [1, 75.31, 316]` |
| кадры сжатия при уходе | `75.31 → 68.85 → 67.24` (2) | `75.31 → 75.11 → 68.25 → 67.24` (4) |
| пик / база | 1.12 | 1.12 (конечный размер не изменился) |

Проверка, что дело не в твине и не в refresh:

- `refresh({ skipIndexation: true })` — 8–12 мс, `applyView` в кадре ховера — 0.2 мс;
  то есть стиль и layout не съедают анимацию.
- Метки времени в серии: первый ОТРИСОВАННЫЙ кадр ховера занимает ~170 мс (`34` → `204`),
  твин, запущенный в нём, полностью сгорал. Отсюда шаг 4 правки — отложенный старт.
- Ступенчатая подача значений твина (0 / 0.25 / 0.5 / 0.75 / 1) даёт непрерывную кривую
  `67.24 / 69.26 / 71.27 / 73.29 / 75.31`: стиль умеет рисовать ЛЮБОЕ положение роста.
- Тот же твин длиной 800 мс — 10–11 монотонных кадров: механизм интерполяции исправен,
  ограничение — частота кадров, а не стиль.

Гейт: `npm run typecheck` — 0 ошибок; `npx vitest run` — 220 passed / 1 skipped;
`npm run build` — ok.
