# План: распределение по плоскости — зазор у мелких нод, кадр принадлежит массе

Дата: 2026-11-12. Запрос: «всё равно маленькие ноды слишком близкие друг к другу, пересмотри
паттерн распространения по плоскости».

## 1. Диагноз (факты)

Раскладка `src/core/graph.ts` гарантирует `dist >= r_a + r_b`, но гарантия считалась не тем радиусом
и в неверном масштабе:

| # | Дефект | Следствие |
| --- | --- | --- |
| 1 | `resolveCollisions` резервирует `node.size` — радиус «под текст» ДО сжатия `visualCoreRadius` | у пыли нарисованная аура (`quad = core + halo`) в 2.3 раза шире резерва: кольца встают вплотную при формально выполненном зазоре |
| 2 | `pxToWorld = targetSpan / 1300`, а кадр рендер фитит по **полному** экстенту, который задают хвосты FA2 | замер: `span/targetSpan = E = 2.56` на 600 нодах ⇒ каждая зарезервированная дорожка на экране в 2.56 раза короче задуманной |
| 3 | Нормировка идёт по квантилям 5–95 %, а `autoRescale` фитит min/max | «плотное пятно в середине + пустые поля»: кадр тратится на выбросы, а не на карту |

Замер до правки (`tools/shot-shape.mjs`, синтетика 600 нод, 900 слов):

| ratio | nnPx p50 | gapPx p10/p50/p90 | minGap | overlap |
| --- | --- | --- | --- | --- |
| 0.6 | 18.6 | 14.8 / 12.5 / 10.9 | 8.4 | 0 |
| 1 | 11.1 | 7.6 / 7.1 / 6.3 | 4.8 | 0 |
| 1.5 | 7.4 | 3.0 / 3.4 / 3.0 | 0.6 | 0 |

`gapPx` — свободная бумага между нарисованными аурами соседей в экранных px.

## 2. Правка

1. `reservePx(size) = max(size, quadOf(visualCoreRadius(size)))` — резерв равен нарисованной ауре,
   но не меньше прежнего радиуса «под текст». Для хабов ничего не меняется (quad < size), у пыли
   резерв растёт в 2.3 раза. `resolveCollisions` не тронут: он по-прежнему принимает радиус как
   `size`, поэтому его контракт и тесты на него не изменились.
2. `squeezeTails(points)` — радиальное асимптотическое сжатие внешней оболочки (за квантом 0.965) в
   `1.05 × r_cut`. Монотонно, непрерывно, направление сохраняется: кадр отдаётся массе, а не хвостам.
   Вызывается для структурных прогонов ПОСЛЕ фрактального прохода: он выталкивает оболочку ещё на 27 %.
3. `fitToSpan(points, span)` — дважды: после нормировки и после `warpPlane`. Нормировка теперь по
   **полному** экстенту (min/max), а не по боксу 5–95 %: рендер фитит min/max, и квантильный бокс
   молча отдавал кадр хвостам. `warpPlane` — деформация, а не масштаб: он сам раздувает экстент в
   1.77 раза (замер), поэтому после него кадр надо пересобрать. Слэк `WARP_FIT_SLACK = 1.2` оставляет
   часть этого раздутия: при 1.0 гейт `(l)` «пустые зоны > 0.38» падает (0.317 — карта читается как
   равномерная решётка), при 1.2 проходит.

## 3. Отвергнутый вариант (важный отрицательный результат)

Перепривязка `pxToWorld` к фактически получившемуся экстенту (итеративный «fixed point»):
`pxToWorld := measuredSpan/1300` → радиусы растут → экстент растёт → … Расходится, потому что
раскладка **масштабно-инвариантна**: дорожка пропорциональна экстенту, и неподвижной точки нет.
Замер: E 2.56 → 5.71 за три прохода, `clarkEvans` 0.72 → 1.26 (равномерная решётка), `clumpRatio`
13 → 5. Поэтому `MAX_SCALE_FACTOR` оставлен 10, а масштаб нормируется жёстко (targetSpan), экстент
же ограничивается сжатием хвостов.

## 4. Результат

| ratio | gapPx p10/p50/p90 до → после | minGap до → после | overlap |
| --- | --- | --- | --- |
| 0.6 | 14.8/12.5/10.9 → **21.6/18.2/19.2** | 8.4 → **13.5** | 0 → 0 |
| 1 | 7.6/7.1/6.3 → **11.7/10.4/10.7** | 4.8 → **7.8** | 0 → 0 |
| 1.5 | 3.0/3.4/3.0 → **5.8/5.6/5.4** | 0.6 → **-0.1** | 0 → 0 |

Цена (честно): контраст сгустков падает — `clarkEvans` 0.72 → 1.04 на 600 нодах (было «кластеры»,
стало «случайное»), `fill` 0.54 → 0.72. Гейт проекта `(l)` «сгустки и пустые зоны» (доля пустых
центральных ячеек > 0.38) остаётся зелёным. Дальше этот компромисс регулируется двумя константами:
`NODE_GAP_RATIO` (воздух) и `TAIL_LIMIT` / `TAIL_CUTOFF_Q` (сколько кадра отдано хвостам).

## 6. Раунд 13 — сильнее распыление (`fitToSpan`)

Запрос: «сделай распыление нод побольше, дисперсию прям сильнее».

Ключ — экстент кадра, а не константа воздуха. Замер по стадиям (600 нод, target 7838): после
нормировки 7838 → после `warpPlane` **16977** (2.17x) → после фрактала 19377 → после солвера 19493.
Кадр раздували сам warp и фрактальный проход. Правка: нормировка по полному экстенту + `fitToSpan`
после warp со слэком 1.2 ⇒ **E = 2.49 → 1.70**, все экранные расстояния выросли в 1.46 раза
без изменения формы.

| ratio | gap p10/p50/p90 до → после | minGap | overlap |
| --- | --- | --- | --- |
| 0.6 | 14.8/12.5/10.9 → **19.0/25.0/20.1** | 8.4 → **14.4** | 0 / 0 |
| 1 | 7.6/7.1/6.3 → **10.0/14.5/11.7** | 4.8 → **8.3** | 0 / 0 |
| 1.5 | 3.0/3.4/3.0 → **4.4/8.3/6.5** | 0.6 → **2.7** | 0 / 0 |

Медиана свободной бумаги выросла на 39–48 %. Гейт `(l)` зелёный.

ГЕОМЕТРИЧЕСКИЙ ПРЕДЕЛ, который надо помнить: при фиксированном числе тел и кадре сумма (тело + зазор)
занимает кадр, поэтому «больше воздуха» математически означает «ровнее распределение». Замер:
`clumpRatio` 13 → 6, `clarkEvans` 1.12 → 1.28. Дальше воздух без потери сгустков не добавить;
единственный честный рычаг за пределами этой инвариантности — меньше нод на кадре (`topN`).
Попытка поднять только `NODE_GAP_*` (1.05 / 4.5) уронила гейт `(l)` до 0.342 и ничего не дала по
форме — константы возвращены к 0.6 / 2.5.
