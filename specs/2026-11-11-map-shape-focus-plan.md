## 1. Диагноз (корневые причины, по пунктам пользователя)

**П.2 «>600 слов — не фигура, а равномерное скопление».** Три независимые причины:
1. `resolveCollisions` получает `scaleFactor=10` и зазор `max(84, size*1.95+28)` в мировых
   единицах — **абсолютный** зазор, не связанный ни с плоскостью, ни с радиусом ноды.
   Для «пылинки» (layout radius 5–8) это ~10× её собственного радиуса, поэтому ограничение
   `dist >= ra+rb` насыщается почти на всех парах: задача превращается в упаковку и
   результат — равномерная решётка. Фрактальные бассейны стираются.
2. Инкрементальный (`fullRun=false`) прогон заново нормирует координаты по квантному боксу
   подмножества и заново гоняет 25 проходов с тем же абсолютным зазором → силуэт теряется
   при любом переключении фильтра, даже первом.
3. LOD: `lodBoost = (order/300)^0.8` (=2.63 при 1000) × `scalePhase` режет мелкие ноды
   до 12 % размера и растворяет их до opacity 0.06 на дефолтном виде; 226 нод скрыты.

**П.3 «частые слова должны быть прям больше редких».** `nodeFitSize` — три широких полосы
по лог-нормировке `t`, плюс `visualCoreRadius` сжимает всё выше 9 px в 0.46 → нарисованный
диапазон почти плоский: редкое 5 px против хаба 34 px, а 90 % слов попадают в одну полосу
5–8 px (`layoutSize` p90 = 8).

**П.1 «выделенная нода должна уезжать наверх, её не должно перекрывать».** Сейчас пин только
включает `isHighlighted` (размер ×1.12). Порядок отрисовки: все рёбра → все ноды (сорт по
`zIndex`) → подписи. Выделенная нода остаётся в бакете `nodes` и её перекрывают соседние
тела и подписи. Sigma v4 даёт ровные `depth`/`labelDepth` (перенос между бакетами **без**
reprocess остального графа) — confirmed по docs (context7).

**П.4 «вход нод дольше и оффсет старта больше».** Сейчас вход — один глобальный
`enterAlpha` 0→1 за 600 мс, без стаггера: все ноды появляются одновременно.

**П.5 «лучше сглаживание».** Кастомные SDF-слои задают feather жёстко: рёбра
`smoothstep(fil-0.32, fil+0.32)` при `fil≈0.7 px` дают ступеньки; `antiAliasingFeather`
(публичная настройка Sigma, дефолт 1) не задан.

## 2. Решения (атомарные шаги)

### Step 1 — закон размеров (п.3): `src/core/geometry.ts`
- `nodeFitSize`: вместо трёх полос один степенной закон от относительной частоты
  `q = count / maxCount`: `r = SIZE_MIN + (SIZE_MAX-SIZE_MIN) * q^SIZE_GAMMA`
  при `SIZE_MIN=4.4`, `SIZE_MAX=76`, `SIZE_GAMMA=0.42`. Монотонность по count сохраняется,
  порядок аргументов `boundA/boundB` нормализуется как раньше.
- `visualCoreRadius`: сжатие выше 9 px ослабить с 0.46 до 0.72 (диапазон 4.4…55 сохраняется),
  чтобы иерархия доживала до экрана.
- Verify: `npx vitest run tests/geometry.test.ts`.

### Step 2 — зазор раскладки пропорционален плоскости (п.2): `src/core/graph.ts`
- В `layout()` после нормировки считать `pxToWorld = targetSpan / SCREEN_SPAN_PX` (1300 —
  эталонная ширина вьюпорта) и передавать в `resolveCollisions`:
  `scaleFactor = min(MAX_SCALE_FACTOR, pxToWorld)`, `padding = GAP_PX * pxToWorld`
  (`GAP_PX = 5`), `padScale = null` — зазор становится долей радиуса, а не абсолютом.
  Порог `dist >= ra+rb` перестаёт насыщаться: ограничение ≈ 20–45 % среднего шага.
- `collisionIterationsForCount`: оставить бюджет (60 проходов на 1000), но пересчитать
  после замера; при недоборе — поднять до 45/проход.
- Verify: `npx vitest run tests/graph.test.ts` + метрики `BENCH=1 npx vitest run tests/bench-tmp-shape.test.ts`.

### Step 3 — фильтры не ломают силуэт (п.2): `src/core/graph.ts`
- Если `!fullRun` и `prevXY` есть у ≥60 % узлов — «reuse frame»: не нормировать повторно
  (координаты уже в финальном кадре), новых узлов ставить в центроид кэшированных соседей
  (+детерминированный джиттер от id), вместо глобального радиального старта; финальная
  релаксация — 12 проходов вместо 25.
- Verify: `npx vitest run tests/graph.test.ts` (кейс: cached-подмножество сохраняет
  относительную геометрию; новые узлы не улетают за габарит кэша).

### Step 4 — мягче LOD, карта дышит на дефолтном виде (п.2): `src/ui/mapview.ts`, `src/ui/mapStyles.ts`
- `lodBoost`: корень вместо степени 0.8 и потолок 1.3.
- `mapDensity`: рампа `(order-50)/550` (насыщается на 600 вместо 400).
- `lodNodeScale`: 0.88 → 0.62; `lodNodeOpacity`: 0.94 → 0.72 (пол расходятся в 3–4×).
- `LOD_FLOOR` не трогать (шум < 2 px скрывается как и раньше).
- Verify: `npm run typecheck` + метрики `tools/shot-shape.mjs` (`hidden ≈ 0`, `labels ≥ 60`).

### Step 5 — выделенная нода наверх, с анимацией подъёма (п.1): `src/ui/mapStyles.ts`, `src/ui/mapview.ts`, `src/ui/subgraphAnim.ts`
- В базовый node-style добавить `depth`/`labelDepth`: при `pinActive && state.isHighlighted`
  → `'topNodes'`, иначе `'nodes'`. Перенос бакета мгновенный (без reprocess), подпись
  рисуется последней — перекрыть её нечем.
- Новое твин-поле `promote` (0→1): размер пина `quadOf(core) * (1 + 0.30*promote)`,
  glow `+0.5*promote`, подпись alpha 1. Пин: `jump(0)` → `to(1, 220)`; снятие: `to(0, 160)`.
- Verify: `npm run typecheck` + проверка в браузере: `getNodeDisplayData(pin).depth === 'topNodes'`,
  скриншот пина.

### Step 6 — длиннее и со сдвигом старта вход нод (п.4): `src/ui/subgraphAnim.ts`, `src/ui/mapStyles.ts`, `src/ui/mapview.ts`
- `enter` становится монотонным временем в мс (`0 → ENTER_TOTAL = ENTER_MS + ENTER_OFFSET`
  при `ENTER_MS=900`, `ENTER_OFFSET=900`), твин линейный, квантование для `enter` 1/240.
- Пер-нодовый прогресс: `delay = phase * ENTER_OFFSET` (phase уже детерминирован по id),
  `p = easeOutCubic(clamp01((enter - delay)/ENTER_MS))`; `p` множит opacity и размер
  (`0.55 + 0.45p`), и alpha подписи. Рёбра — глобальный fade по тому же времени.
- Verify: `npm run typecheck` + замер (первый кадр: доля нод с `opacity > 0.5` растёт монотонно).

### Step 7 — сглаживание (п.5): `src/ui/neural.ts`, `src/ui/mapStyles.ts`
- `antiAliasingFeather: 1.3` в `MAP_SIGMA_SETTINGS`.
- `layerAxon`: feather тела 0.32 → 0.55 px (аналитическое сглаживание тонких волокон).
- `layerSoma`: мягче кромка диска (`-0.7…0.8` вместо `-0.5…0.6`), те же +0.15 px у штрихов.
- Verify: `npm run build` + скриншот кропа.

### Step 8 — верификация и отчёт
- `npm run typecheck && npm run test && npm run build`.
- `tools/shot-shape.mjs after-271/600/1000` + пин-скриншот; сравнение метрик с baseline.
- `specs/verifications/2026-11-11-map-shape-focus.md`.
- Обновить `TASK_STATE.md` и `HANDOFF.md` (физика/тесты).

## 3. Границы (не делаем)

- Новых зависимостей, UI-фреймворков, словарных лемматизаторов — нет.
- Формат экспорта и воркер-пайплайн вне `nodeFitSize`/`layout` не трогаем.
- Сетевых вызовов нет; синтетика генерируется в памяти.
- Уже отклонено: `zIndex` для пина (репроцесс каждый кадр твина), глобальное увеличение
  `PAD` (ломает мелкие карты), второй проход FA2 (стоимость без гарантии формы).

## 4. Риски

1. Уменьшение зазора → больше визуальных касаний тел на плотных картах. Откат: `GAP_PX`.
2. Смена закона размеров меняет упаковку и `autoRescaleContent: 'nodes'` → на 271 нодах
   карта может стать крупнее. Откат: `SIZE_MAX/GAMMA`.
3. Перенос пина в `topNodes` может задеть буфер подписей (в коде есть комментарий о прошлом
   регрессе) — проверяется скриншотом и `labels ≥ 60` после пина.
