# План 2026-11-07 (4) — обзор как «хребет», двухступенчатый LOD

Статус: **РЕАЛИЗОВАНО** (вердикт: `specs/verifications/2026-11-07-overview-spine.md`).
Предыдущее: `specs/2026-11-07-axon-tracts.md`.
Вердикт предыдущего: `specs/verifications/2026-11-07-axon-tracts.md`.

## 0. Отзыв пользователя
Скриншот реальной карты (600 узлов / 1212 рёбер): «визуальный шум сохранился —
все такие же большие полосы у всех», «пути не склеиваются, а просто разбросаны
везде», «не следуешь дизайну». Три требования:
1. Рёбра к нодам, почти исчезнувшим из-за LOD, тоже становятся прозрачнее.
2. Маленькие ноды недостаточно маленькие — видны только при приближении.
3. Прозрачность в LOD — последний «быстрый» этап, первый этап — масштаб.

## 1. Диагноз (замер CDP на реальном экспорте, ratio 1)
| Метрика | Значение |
|---|---|
| strength p0 / p50 / p100 | 0.071 / 0.168 / 1 |
| opacity p0 / p50 / p100 | 0.154 / 0.193 / 1 |
| рёбер в трактах | 1199 / 1212 |

1212 линий с альфой ≈0.19 дают сплошную дымку. `bundle = 1` у почти всех —
то есть «плотность тракта» перестала что-либо различать. Белые слитки у «меня» —
это десятки прядей одного тракта, наложенных друг на друга до чистого белого.
Мелкие ноды: `drawnCore` 5…9 px, LOD гасит их только по альфе, размер остаётся —
поэтому сотни точек одинакового калибра читаются как шум.

**Корневая ошибка дизайна:** обзор трактовался как «уменьшенная копия детального
вида». Нужен не масштаб, а **другой объект**: скелет — хабы, топ-связи и по одной
чистой кривой на тракт. Детали проявляются при зуме-ин.

## 2. Дизайн: три уровня раскрытия
| Уровень | cameraRatio | Что видно |
|---|---|---|
| Деталь | ≤ 0.45 | всё: мелкие ноды в полный размер, все пряди, все связи |
| Переход | 0.45 … 0.80 | **этап 1 — масштаб**: мелкие ноды и толщина рёбер сжимаются, прозрачность ещё не тронута |
| Обзор | ≥ 1.0 | **этап 2 — быстрая прозрачность**: короткий резкий рамп убирает дымку; остаются хабы, топ-связи и хребет тракта |

Три фазы (все по **реальному** `cameraRatio`, без density-боста `lodRatio`):
```
scalePhase = smoothstep(0.40, 0.88, r)   // первый, плавный
fadePhase  = smoothstep(0.78, 1.06, r)   // последний, быстрый, короткий
deepPhase  = smoothstep(1.00, 2.20, r)   // частота при глубоком отдалении
```

## 3. Механика

### 3.1 Хребет тракта — `rank` (`src/core/geometry.ts`)
В `bundleEdges()` после всех проходов: сгруппировать по стабильному ключу
`hub:сектор`, отсортировать по `strength` (убыв.) и присвоить `rank` 0…N-1.
`BundleInfo += rank`. Ноль = самая сильная связь = ось тракта.
Проводка: `WorkerEdge.rank` → атрибут ребра → `edges.variables.rank`.

### 3.2 Этап 1 — масштаб
- `lodNodeScale(core, r) = 1 − 0.88·small·scalePhase`, `small = clamp((18−core)/13,0,1)`.
  Маленькая нода 5 px → 0.6 px на обзоре, хаб ≥18 px не меняется.
  Применяется к `nodes[].size` (квад), а не к `opacity`.
- `edges[].size = attrs.size · (1 − 0.3·scalePhase)`.
- Новый атрибут шейдера `lod = scalePhase` → `fil *= 1 − 0.5·lod`,
  `glow *= 1 − 0.6·lod`. Толщина уходит ДО прозрачности.

### 3.3 Этап 2 — быстрая прозрачность
```
opacity = freq · ends · spine · isolated
freq     = 0.14 + 0.86 · s^(1 + 3·deepPhase)          // топ ярче, остальные по убыванию
ends     = 0.10 + 0.90 · smoothstep(0.6, 5.5, rendered) // п.1: связь гаснет вместе с нодой
spine    = 1 / (1 + 0.9 · rank · fadePhase)             // только ось тракта, не 50 прядей
isolated = 1 − 0.82 · fadePhase · (1 − bundle)          // разбросанные одиночки уходят
```
`rendered = renderedNodeSize(core, r) · lodNodeScale(core, r)` — берётся от
`attrs.lodSize` (min размера концов). Все множители, кроме `freq`, включаются
только на коротком `fadePhase`, то есть **после** этапа масштаба.

Узлы: `lodNodeOpacity(..., g) = base · (1 − 0.94·small·fadePhase)`.
Подписи, `pinActive`, hover/pin и эго-сеть сохраняют прежнее поведение:
активные ноды и рёбра форсируются в полную яркость вне LOD.

## 5. Критерии приёмки
- Preflight зелёный, тестов ≥ 154, исключений 0.
- На реальном экспорте при ratio 1: дымка ушла, белых слитков нет, читается
  скелет из нескольких трактов; при ratio 0.45 деталь возвращается.
- Число фактически видимых рёбер (opacity > 0.05) падает кратно;
  top-связи остаются самыми яркими.
- Hover/pin/подписи без регрессий. Вердикт + скриншоты → `specs/verifications/`.

## 6. Риски
| Риск | Мера |
|---|---|
| Обзор опустеет | калибровка по реальному экспорту, `ends` имеет пол 0.10, `freq` пол 0.14 |
| Пропадёт «нейронность» | пряди возвращаются на зуме-ин (`fadePhase → 0`) |
| `rank` сломает типы | правим types/worker/mapview одной правкой + typecheck |
| Мелкие ноды станут некликабельны | на зуме-ин `scalePhase → 0`, размер полный; pin форсирует размер |
| Новый uniform/атрибут не доедет | `lod` идёт как обычный style-атрибут (как `strength`) |

## 7. Уточнения, найденные при реализации
- Первая версия гасила «лишние пряди» **внутри** каждого тракта (`rank`). На реальной
  карте это дало по одной случайной линии от каждого из сотен трактов — шум остался.
  Добавлен **`tractRank`**: ранжируются целые коридоры по суммарному весу, и на обзоре
  выживает скелет из нескольких трактов (`skeleton = 1 − fade·smoothstep(6,22,tractRank)`).
  Видимых рёбер 1212 → 142 на ratio 1.
- Выяснилось, что группировка «хаб + общий центроид» даёт **звезду**, а не склеенный
  тракт: сильные рёбра (хребет) намеренно гнулись меньше и оставались прямыми.
  Переделано: проход 0 строит **общую ось** хаба (все волоски уходят по среднему
  направлению, каждый со своей длиной, без укорачивания), проходы 1–2 доминируют и
  сливают параллельные рёбра разных хабов в длинный коридор.
- Сильное стягивание + независимый clamp коэффициентов давал **изломы** на хребтах.
  Введено ограничение смещения контрольных точек `|C − C_straight| ≤ 0.26·len`
  в мировых координатах; изломы исчезли.
- На малой фикстуре (33 узла) подавление оказалось избыточным — карта почти пустела.
  Агрессивность LOD теперь масштабируется `mapDensity = clamp((order−50)/350)`
  (graphState, считается в `applyView`): маленькие чаты остаются детальными, шум
  подавляется только на плотных картах. Проверено: 28/28 рёбер и полный размер нод.
- Порядок стадий уточнён до непересекающегося: `scalePhase = smoothstep(0.35,0.78,r)`
  (масштаб), `fadePhase = smoothstep(0.82,1.05,r)` (короткая быстрая прозрачность).
  Замер: при r 0.55 видны 885 рёбер, но малые ноды уже 4.85 px вместо 8;
  при r 1.0 ноды 0.96 px и рёбер 142. То есть масштаб сработал первым.
- `spine` получил небольшой всегда-включённый пол (`0.16·mapDensity`), иначе при
  сильном зуме-ин плотный пучок снова выгорал в сплошную белую полосу.
